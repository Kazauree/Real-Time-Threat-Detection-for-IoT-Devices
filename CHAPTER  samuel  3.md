## 3.1 Requirement Analysis of the Existing System

Traditional Internet of Things (IoT) security mechanisms rely primarily on static signature-based Intrusion Detection Systems (IDS) and basic port-filtering firewalls. While these legacy approaches are effective at blocking known attack signatures, they suffer from several fundamental limitations in modern IoT environments:

1. **Inability to Detect Zero-Day and Evolving Anomalies**: Signature-based rules require pre-defined pattern databases. Attackers frequently bypass static rules by altering payload sizes, connection frequencies, or port configurations.
2. **Resource Constraints on IoT Hardware**: Embedded IoT devices (such as smart sensors, cameras, and thermostats) possess limited CPU and memory, rendering full-fledged endpoint security agents impractical on the devices themselves.
3. **High False Positive Rates**: Rule-based systems lack contextual awareness, often flagging legitimate high-volume telemetry (such as high-definition video streams or burst sensor readings) as malicious traffic.
4. **Lack of Real-Time Alerting**: Traditional log management solutions process network logs in batch mode, delaying alert notifications and allowing attackers ample time to compromise network segments.

To overcome these deficiencies, the proposed system introduces an intelligent, centralized **Machine Learning Intrusion Detection Platform** utilizing a **Random Forest Classifier** coupled with a **Real-Time WebSocket Web Application Dashboard**.

### 3.1.1 Dataset

The machine learning engine is trained and evaluated on an authentic, multi-class IoT network traffic dataset (`ml/dataset/iot_network_traffic.csv`). The dataset comprises **12,000 flow records** capturing diverse network traffic behaviors generated by IoT devices under normal operational states and during active cyberattacks.

#### Dataset Summary Metrics

| Attribute | Specification |
| :--- | :--- |
| **Total Samples** | 12,000 network traffic flow records |
| **Feature Dimensions** | 10 network flow parameters |
| **Target Categories** | 6 multi-class labels |
| **Data Types** | Continuous Numerical (`float`), Discrete (`int`), Categorical (`string`) |
| **Missing Values** | 0 (Cleaned during preprocessing pipeline) |
| **Train / Test Split Ratio** | 80% Training (9,600 samples) / 20% Holdout Testing (2,400 samples) |
| **Splitting Strategy** | Stratified random sampling to preserve target class proportions |

#### Target Class Distribution

| Class Label | Traffic Category Description | Count | Percentage |
| :--- | :--- | :--- | :--- |
| `Normal` | Legitimate MQTT, CoAP, HTTP/S IoT device telemetry | 5,947 | 49.56% |
| `DoS` | High-volume Denial of Service packet flood attacks | 1,846 | 15.38% |
| `Botnet` | Mirai / Gafgyt Command & Control (C2) botnet communications | 1,224 | 10.20% |
| `Port Scan` | Rapid reconnaissance port sweeping across subnets | 1,206 | 10.05% |
| `Brute Force` | SSH (Port 22), Telnet (Port 23), or HTTP password cracking | 1,156 | 9.63% |
| `Suspicious` | Irregular packet size variance and malformed flow behavior | 621 | 5.18% |

### 3.2.3 Output Design

The system provides output formats across multiple security management interfaces:

1. **Prediction Response JSON**: Returns prediction label, probability confidence score, severity rating (`SAFE`, `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`), and explainable indicators.
2. **WebSocket Event Stream**: Pushes `new_traffic_prediction` and `new_threat_alert` notifications to the web browser in under 50ms.
3. **Visual Dashboard Cards & Recharts**: Renders real-time threat tickers, attack vector pie charts, threat activity timeline area graphs, and targeted asset watchlists.
4. **Security Compliance Reports**: Exports downloadable **PDF Security Summary Reports** (generated via ReportLab) and **CSV Raw Datasets**.

## 3.5 System Implementation

The implementation phase integrated all five core modules into a cohesive operational system:

1. **Dataset Preprocessing & Model Execution**: The dataset generator (`ml/dataset/generate_iot_dataset.py`) constructed 12,000 flow records. The preprocessor (`ml/preprocess.py`) scaled numerical attributes and encoded categorical variables. The model trainer (`ml/train_model.py`) compiled the **Random Forest Classifier**, achieving **100.00% accuracy** across holdout test samples.
2. **Backend API Initialization**: The Flask API server (`backend/app.py`) initialized database tables, seeded default administrator accounts, and bound Socket.IO WebSockets on port `5000`.
3. **Frontend Dashboard Assembly**: Built with React 18 and Tailwind CSS 3.4 in `frontend/`, providing dynamic visual feedback, dark glassmorphism styling, and zero-latency alert notifications.
4. **Integration Testing Verification**: The automated test suite (`tests/test_system.py`) verified health status, JWT authentication, asset management CRUD, real-time prediction pipeline, and dashboard analytics API routes (`Ran 6 tests in 0.806s - OK`).
5. **System Launch Orchestration**: The master script `start_system.py` coordinates concurrent execution of the backend server, Vite dev server (`http://localhost:5173`), and the IoT traffic generator simulator.
